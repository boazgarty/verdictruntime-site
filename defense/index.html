The guard in detail: every tool call checked before it runs

The guard sits between your AI agent and its model provider. Each time the model proposes a tool call, such as sending an email or saving a note to memory, the guard checks it against your rules. In enforce mode, a call that breaks a rule is removed before the agent can run it. A second guard does the same between an AI client and its MCP tools.

Outside recipients

Holds an email, invite or message to anyone outside your organisation, and a web request that carries your data out.

Protected values

Holds an action whose text contains card or bank account numbers, API keys, or any value you mark as protected, such as the agent's system prompt.

Memory writes

Holds a write to the agent's memory when outside content, such as an email or a web page, triggered it, so one message cannot plant a standing instruction.

Owner approval

Where a rule asks for a human decision, the action waits for the owner to approve or reject it. An approved call is released once. The held call is stored encrypted and expires.

MCP tools

Hides MCP tools you did not approve, and refuses a tool whose description or parameters changed after you approved it.

Observe first, then enforce

It starts in observe mode: it records what it would have held and changes nothing. It ships as a container that runs next to your agent; you point the agent at the guard's address.

What we tested. We ran the guard end to end in front of unmodified LangGraph, OpenAI Agents SDK, CrewAI and AutoGen agents, over OpenAI Chat Completions, the OpenAI Responses API and Anthropic Messages, streaming and non-streaming. In those runs, none of the tool calls the guard held was executed (checked against each tool's own record), while the same calls did run when the guard was removed. The MCP guard was tested with the official MCP Inspector client. The guard's logs record which rule fired and which tool was involved, not the text of prompts or responses.

What that does not show. Those tests used a scripted model in place of the provider. They show that the guard intercepts and removes the calls; they do not show how often a real model would propose one, and we make no claim about stopping real attackers. Not every framework was run on every format.
